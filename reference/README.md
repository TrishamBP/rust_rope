# PyTorch reference validation (tooling, not production code)

This folder contains an **independent** PyTorch implementation of RoPE. Its
only purpose is to check the Rust implementation in `src/`. The Rust library
does not use it, and it never calls Rust code.

| File | Purpose |
|---|---|
| `pytorch_rope.py` | The reference: inverse frequencies, positions, angles, `cos`/`sin`, interleaved and split-half rotation, partial RoPE, scaling methods (Stage 8). |
| `compare_rope.py` | Reads the Rust cases, recomputes them in float64 and float32, reports errors, checks tolerances. Exit code 0 = all pass. |
| `test_pytorch_rope.py` | Self-tests of the reference, and negative controls (a wrong layout, base or start position must fail). |
| `requirements.txt` | The Python packages. |
| `data/rust_cases.txt` | Generated by Rust. Not committed (git-ignored). |

## Setup (one time)

```bash
python -m venv reference/.venv
reference/.venv/Scripts/python -m pip install -r reference/requirements.txt --index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.org/simple
```

(On Linux or macOS, use `reference/.venv/bin/python`.)

## Run the validation

```bash
cargo run --example export_reference_cases                   # Rust writes inputs + outputs
reference/.venv/Scripts/python reference/compare_rope.py     # compare
reference/.venv/Scripts/python -m unittest discover -s reference -v
```

## Data exchange

Rust writes a plain text file. Each case has one `case` line with the
configuration, one `input` line and one `output` line. Rust prints each
`f64` with `{:?}`, which is the shortest decimal text that converts back to
the identical `f64`; Python's `float()` reads it back exactly. Thus the
exchange adds no rounding error.

## Tolerance

`tol = 8 · eps · (1 + max_angle) · max(1, max|x|)`, with `eps = 2^-52`
(float64) or `2^-23` (float32). See `explain.md`, Entry 13.
